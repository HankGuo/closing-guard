# 事件触发的闭店自动巡检（重定位草案）

> 这是对当前 Demo 的重新定位，不是新代码。目标：把“谁去拍照”这个死结解开。

## 1. 链路（有闭环）

```
关灯/关门（智能开关或门磁）
        ↓ 触发
关键点摄像头抓拍（闲置手机 / 旧摄像头）
        ↓ 图片 + 时间戳
本地小模型判断（关没关、有没有异常）
        ↓
异常 → 推送负责人（微信/企微/短信）或现场广播
正常 → 静默留档
```

**与旧方案的区别**：不再要求店员逐项拍照；触发来自物理事件（关灯），拍摄由设备完成，人只处理异常。

## 2. 角色与激励

| 角色 | 旧方案 | 新方案 |
|---|---|---|
| 店员 | 必须拍，纯负担 | 不参与，关灯即可 |
| 店主/负责人 | 事后才看 | 异常实时收到推送 |
| 物业/连锁 | 不采信自制记录 | 可拿到带时间戳的抓拍记录 |
| 设备 | 手机当取景器 | 手机/旧摄像头当固定监测点 |

## 3. 成本对比（按单店 2 个点位估）

| 方案 | 硬件 | 年费 | 备注 |
|---|---|---|---|
| 商用 AI 摄像头（萤石/海康类） | 200–600 元/台 | 100–300 元/台/年（云存储/AI） | 成熟、稳定、有售后 |
| 本项目（闲置手机 + 本地 hub） | 支架/充电 30–50 元/点 | 0（本地推理） | 依赖旧手机稳定性；需一台本地主机 |

**卖点只能是“存量设备盘活 + 零云费 + 数据不出店”，不能是“更准”。**

## 4. 竞品（必须承认）

- 萤石/海康：AI 摄像头 + 云订阅，成熟
- 米家/涂鸦：摄像头 + 自动化场景，便宜
- 慧运营/万店掌：巡店 SaaS + 固定摄像头
- 大羽 AI：燃气隐患拍照识别，政企渠道

**差异点**：不卖硬件、不卖云、用店里已有的旧手机；适合“有闲置设备、又不想付年费”的小店/小连锁。

## 5. 先验证，再写代码

在 1–2 家真实店铺做 7 天试点，只测四件事：

1. 关灯触发成功率（智能开关/门磁）
2. 抓拍可用率（角度、光线、遮挡）
3. 误报率（把正常画面判成异常的比例）
4. 负责人收到推送后的响应率

**四项里任何一项不达标，这个方向就不成立**——不再先写代码再找场景。

## 6. 已知风险

- 旧手机长期插电：电池鼓包、发热、系统杀后台
- 固定视角拍不到柜内阀门/门锁内侧
- 本地模型对“阀门角度”判断弱，误报会让人关掉通知
- 触发依赖智能开关，没有智能开关的店用不了
